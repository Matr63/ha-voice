# Установка HA Voice

Плата Waveshare — только микрофон и динамик. Всё остальное — ключевое слово,
распознавание (GigaAM), кто говорит, дневник, ИИ для дома и голос ответа (Kokoro) —
работает на ПК в HA Voice. Home Assistant нужен только как «дом»: датчики и сервисы.

```
Waveshare ──PCM 16 кГц──▶ HA Voice (ПК) ──состояния/сервисы──▶ Home Assistant
          ◀──Kokoro PCM──
```

Wyoming, пайплайн Assist и Piper для этого **не нужны**.

## A. Add-on на HAOS / Supervised (рекомендуется)

1. **Настройки → Дополнения → Магазин → ⋮ → Репозитории** → `https://github.com/Matr63/ha-voice`.
2. Установите **HA Voice** (первая сборка 15–45 мин из‑за torch и llama.cpp; прогресс — в **Журнале**, строки `[ha-voice N/6]`).
3. **Запустить**. Первый старт качает веса GigaAM и Kokoro‑ru (`waiting STT…` / `waiting TTS…`).
4. Дополнение само кладёт интеграцию в `custom_components` и показывает уведомление —
   **перезапустите Home Assistant**. Затем **Настройки → Устройства и службы** →
   «Обнаружено: HA Voice» (или «Добавить интеграцию → HA Voice» — адрес найдётся сам).
5. Откройте панель **HA Voice** → вкладка **Колонка** → «Скачать последнюю» прошивку.

## B. Отдельный сервер (Docker Compose)

1. `.env.example` → `.env`: `HA_URL` и `HA_TOKEN` (Профиль HA → Безопасность → Долгосрочные токены).
2. `docker compose up -d --build`
3. Панель: `http://IP:8088/`.
4. Интеграция: скопируйте `custom_components/ha_voice` в `/config/custom_components/`, перезапустите HA,
   добавьте **HA Voice** и укажите `IP`, порт `8088`.
5. Ollama на этом же ПК: вкладка **Ассистент** → «LLM», адрес
   `http://host.docker.internal:11434/v1`, модель с tool calling (qwen2.5:7b, llama3.1:8b).

## C. Колонка Waveshare ESP32‑S3‑AUDIO

Один файл прошивки: [esphome/ha-voice-satellite.yaml](esphome/ha-voice-satellite.yaml).
Готовые `factory.bin` / `ota.bin` собирает CI (релиз `firmware-latest`), панель скачивает их сама.

1. **Первый раз — USB.** Панель → **Колонка** → «Первая прошивка по USB»:
   кнопка «Прошить по USB» (Chrome/Edge по HTTPS) или `factory.bin` через
   [web.esphome.io](https://web.esphome.io).
2. **Wi‑Fi:** там же через Improv, или с телефона подключитесь к точке **HA-Voice-Setup**.
3. Колонка сама подключается к `homeassistant.local:10500`. Другой адрес (compose) —
   сущность **«Сервер HA Voice»** у устройства в HA или веб‑страница платы `http://<ip>/`.
4. **Дальше — по сети:** Панель → **Колонка** → «Обновить по сети». Кабель не нужен.

Собрать самому: `cd esphome && esphome run ha-voice-satellite.yaml`
(свой адрес: `esphome -s ha_voice_host 192.168.1.50 run ha-voice-satellite.yaml`).

На колонке один переключатель **«Слушать»** (по умолчанию включён) — выключает микрофон
целиком. Средняя кнопка — сказать команду без ключевого слова / остановить ответ.

## D. ReSpeaker XVF3800 4‑Mic Array + XIAO ESP32‑S3

Прошивка: [esphome/ha-voice-xvf3800.yaml](esphome/ha-voice-xvf3800.yaml), релиз —
`ha-voice-xvf3800.factory.bin` / `.ota.bin`. Работает так же, как Waveshare, но звук
готовит DSP XMOS XVF3800: 4 микрофона, направленный луч, эхо‑ и шумоподавление.
Драйверы XVF3800 и кодека AIC3104 — из
[formatBCE/Respeaker-XVF3800-ESPHome-integration](https://github.com/formatBCE/Respeaker-XVF3800-ESPHome-integration).

1. Панель → **Колонка** → «Прошивка колонки» → **Плата: ReSpeaker XVF3800** → «Скачать последнюю».
2. Кабель USB‑C в **XIAO ESP32‑S3** (разъём дальше от аудиовыхода 3.5 мм) и:
   - **в USB сервера Home Assistant** — «Первая прошивка по USB» → вариант 1: выберите порт
     (`Espressif …`) → «Прошить». Нужен доступ к USB (`uart: true` уже в дополнении);
   - **или в USB своего компьютера** — кнопка «Прошить по USB из браузера» (панель по https)
     или `factory.bin` через [web.esphome.io](https://web.esphome.io).
3. Wi‑Fi — Improv или точка **HA-Voice-Setup**, как у Waveshare.
4. При первом включении плата сама прошивает DSP XVF3800 I2S‑прошивкой (~1 мин, кольцо
   фиолетовое) — не отключайте питание. Сущность **Состояние чипа DSP** должна показать `OK`.
5. Дальше — «Обновить по сети», панель сама берёт сборку под подключённую плату.

Если **Состояние чипа DSP** — «Нет ответа»: на XVF3800 стоит USB‑прошивка Seeed без I2C. Один раз:
`dfu-util`, кабель в USB‑C **XMOS** (ближе к 3.5 мм), `dfu-util -l` (должен быть
`reSpeaker DFU Upgrade`), затем
`dfu-util -R -e -a 1 -D respeaker_xvf3800_i2s_master_v1.0.9_48k.bin` (файл — в репозитории formatBCE).
Не находится — держите кнопку Mute при включении питания.

Кольцо из 12 светодиодов показывает те же состояния, что и у Waveshare; кнопка Mute
выключает микрофоны в самом DSP (красные метки на кольце). Канал: 0 — comms‑луч
(шумоподавление + АРУ), 1 — ASR‑луч; в «авто» речь идёт из comms, ключевое слово — из ASR.

Настройки чипа — панель → **Колонка** → «Звук чипа XVF3800», свои у каждой платы:
подавление шума, приглушение пауз, срез низких частот, автоусиление, усиление канала
ключевого слова и луч микрофонов. Шумоподавление и автоусиление действуют только на канал
речи; на ключевое слово влияет усиление его канала и луч. Под каждой настройкой видно, что
чип ответил на самом деле; пока значение не меняли, оно только читается из чипа. Если панель
пишет, что чип не отвечает или значение не совпадает, эту настройку лучше не менять.

Там же кнопки «Слушать канал речи» и «Слушать канал ключевого слова»: микрофон платы звучит в
браузере с задержкой около секунды, с тем же усилением, что идёт на распознавание. Лучше в
наушниках. Трансляция идёт только после нажатия и заканчивается кнопкой «Стоп», при уходе с
вкладки, смене платы или разрыве связи.

## Своя LLM на сервере Home Assistant

Панель → **Ассистент** → «Своя модель на этом сервере». Работает в дополнении
(llama.cpp, процессор), интернет нужен только чтобы скачать модель.

- **Скачать**: готовые модели с HuggingFace (Qwen2.5 1.5B/3B, Qwen3 4B Instruct 2507,
  T‑lite 7B, Qwen2.5 7B) или любая ссылка на `.gguf`. Обрыв — докачка с того же места.
- **С диска ПК**: «Загрузить .gguf с компьютера», или положите файл в
  `/share/ha-voice/llm` через Samba.
- **Запустить и использовать** — модель грузится в память, ассистент переключается на
  LLM `http://127.0.0.1:10360/v1`. После перезапуска дополнения поднимается сама.
- Ориентир: N100 / 8 ГБ — 3–4B Q4_K_M (ответ 3–8 с); 1.5B — для слабых машин.
  Модели лежат в `/share`, поэтому не раздувают резервные копии дополнения.
- **Почему первый ответ долгий.** Модель на процессоре читает список устройств (сотни
  строк) медленно. Список держится неизменным, поэтому llama.cpp читает его один раз
  (сразу после запуска модели) и дальше — только новую фразу. Первая команда после
  добавления устройств в HA снова дольше. Меньше доменов в «Что доступно ассистенту»
  — быстрее. Пока ассистент думает, в панели видно: «Думаю 5 с · обычно ~3 с · шаг».

## Kokoro офлайн и «загружается»

Голос Kokoro‑ru и словарь ударений RUAccent (~1 ГБ) скачиваются с HuggingFace
**один раз** в `/data/models` (`kokoro-ru/`, `ruaccent/`). Дальше Kokoro стартует без
интернета; мелкие файлы сверяются с HF не чаще раза в неделю и только если HF отвечает.
Прерванная загрузка докачивается при следующем запуске.

Если с сервера HuggingFace не открывается — **Озвучка → «Модели Kokoro офлайн»**:

1. На ПК: `pip install huggingface_hub`, затем
   `python scripts/kokoro_models.py` (зеркало: `--endpoint https://hf-mirror.com`) →
   `ha-voice-kokoro-models.zip`.
2. Кнопка **«Загрузить архив с ПК (.zip)»** — модели распакуются, Kokoro перезапустится.

С работающего сервера архив можно забрать кнопкой «Скачать архив моделей».
Там же видны этап загрузки, ошибка, журнал и кнопка «Перезапустить»; упавший Kokoro
дополнение перезапускает само. Зеркало для самого дополнения — `hf_endpoint` в Конфигурации.

## Звуковые сигналы

Озвучка → **«Сигнал „слушаю“»** (короткий восходящий звук после ключевого слова, кнопки
или в ожидании ответа на уточняющий вопрос) и **«Сигнал ошибки»** (не расслышала, голос
не узнан, команда не выполнилась). Громкость сигналов — отдельно, кнопками рядом можно
прослушать на колонке. Пока звучит сигнал, микрофон колонки не слушается.

**Свой звук:** «Свой WAV» рядом с сигналом — WAV без сжатия, до 6 секунд (любая
частота, моно или стерео); «Встроенный» возвращает стандартный. Файлы лежат в
`/data/sounds`.

**Сколько ждать команду** (Ассистент → «Фраза активации»): если после ключевого слова
за это время не начать говорить, колонка перестаёт слушать. По умолчанию 6 с.

Если сигнал прозвучал один раз и дальше колонка молчит, обновите прошивку: в ней
исправлено зависание плеера на коротких звуках. Сервер (2.2.4+) тоже сам сбрасывает
плеер, если колонка не подтвердила конец звука.

**Фраза, пока ассистент думает** (Озвучка): если ответ готовится дольше порога
(по умолчанию 3 с), колонка говорит одну из фраз: «думаю», «секунду»… Точно предсказать
время нельзя — число шагов выбирает сама модель. Поэтому порог работает как таймер, а
фраза звучит сразу, если LLM обычно отвечает дольше порога (медиана последних 10 ответов)
или ей предстоит заново читать список устройств. Фразы озвучиваются заранее и не
нагружают процессор, когда он занят моделью.

**Подсказки для комнат** (Устройства, в заголовке комнаты): как ещё вы её называете, например
«столешница, у холодильника». Подсказка у датчика говорит, что именно он измеряет: датчику
внутри холодильника напишите «в холодильнике». Подходящего датчика нет — колонка так и скажет.

**Значения датчиков без модели** (Ассистент): на «температура в зале» датчик находится кодом по
комнатам, их подсказкам, именам приборов и подсказкам датчиков, а значение берётся из HA.
«Температура на улице» читается из датчика с такой подсказкой, а если его нет — из сущности
погоды. Сразу после ответа работает и короткое «а в зале?». Команды, прогноз и вопросы о прошлом
идут в LLM. В журнале команд у каждой записи есть «Что ушло ассистенту и что вернулось»: запрос,
ответы модели и вызовы функций. Системный промпт там не повторяется: виден только факт, что он
тот же, или строки, которые изменились.

**Промпт модели** (Ассистент): правила для модели можно прочитать и изменить прямо в панели,
«Вернуть стандартный текст» отменяет правку. Справочник устройств собирается сам.

**Списки, заметки и журнал** (вкладка «Списки»): «добавь в список покупок на дачу молоко и хлеб»,
«что в списке для дачи», «какие есть списки», «вычеркни молоко из списка покупок», «запиши
заметку…», «запомни, что…», «запиши в журнал…», «что в журнале». Обычные фразы понимает код и
отвечает сразу. Списка нет или название подходит к нескольким — колонка переспросит; на ответ
есть 45 секунд. Фразы, которые код не разобрал, идут в модель с отдельным коротким промптом. Он
живёт в своём слоте llama.cpp и не вытесняет из кеша большой промпт дома. Записи лежат в
`/data/notes.json` и попадают в резервную копию дополнения.

**Плагины для LLM** (вкладка «Плагины»): данные для ассистента, которых нет в Home Assistant.
Первый плагин — **погода со страницы**. Укажите адрес страницы с прогнозом для своего города и
сколько раз в сутки её открывать (по умолчанию 2). Дополнение скачивает страницу и берёт из неё
текст про погоду. Модель из «Ассистента» читает этот текст в отдельном слоте llama.cpp, поэтому
кеш команд не сбрасывается. В этом запросе у модели одна функция, `report_weather`, и страница не
может ничего сделать с домом. Числа, которых нет на странице, отбрасываются. «Какая погода»,
«погода на завтра», «какая погода в субботу» и короткое «а послезавтра?» колонка отвечает сразу,
без модели. На остальные вопросы («нужен ли завтра зонт») модель отвечает через функцию
`get_weather`. В панели видно, что модель получила со страницы, что ответила и что скажет колонка.
Не подходят страницы, где погода рисуется скриптом: на них почти нет текста, и панель об этом
скажет. При ошибке плагин повторяет попытку через 15 минут. Настройки и результат лежат в
`/data/plugins.json`.

**Поиск в интернете** срабатывает на ключевые фразы: «поищи в интернете…», «найди в интернете…»,
«загугли…». Список фраз можно поменять. Остальная часть фразы уходит в поисковик. Дополнение берёт
первые результаты и текст первой найденной страницы, а модель отвечает по ним одной-двумя фразами.
В этом запросе у модели одна функция, `say_answer`. Google отдаёт результаты и свой «ответ ИИ»
только браузеру со скриптами, поэтому поиск идёт через DuckDuckGo. Если DuckDuckGo не пускает,
укажите свой SearXNG (в его `settings.yml` должен быть включён формат `json`). Если сказать только
«поищи в интернете», колонка спросит «Что поискать?».

**Спроси у брата** отправляет вопрос другой модели через интернет. Подойдёт любой OpenAI-совместимый
API: OpenAI, OpenRouter, DeepSeek, Claude, Ollama на другом компьютере. Брату уходит только сам
вопрос и пара последних его ответов, чтобы работало «спроси у брата, а почему?». Дом ему не виден.
Ключ API хранится в дополнении, в панель он не возвращается. Поиску можно поручить пересказ
через брата: так быстрее, чем на процессоре, но найденное уходит ему.

## Несколько колонок (комнаты)

Колонок может быть сколько угодно: каждая сама подключается к серверу (поле
«Сервер HA Voice» на её веб-странице, если сервер не нашёлся сам). Панель → Колонка →
**«Колонки и комнаты»**: кнопка с именем выбирает, какую колонку показывают вкладки
«Колонка» и «Озвучка».

- **Комната** берётся из области платы в HA (Настройки → Устройства и службы → ESPHome →
  плата → Область) или выбирается там же в панели. «Включи свет» без названия комнаты
  выполнится в комнате колонки, которая услышала; LLM тоже знает комнату.
- **Ключевое слово услышали обе колонки** — отвечает та, что услышала первой, вторая
  молчит 3,5 с. Дневник записывает фразу один раз.
- Голоса, фразы активации, звуки и ассистент общие для всех колонок.
- **Динамик / Звук на.** Если к плате не подключён динамик (часто у XVF3800), снимите
  «Динамик»: ответы и сигналы этой колонки зазвучат на другой — выбранной в «Звук на»
  или на колонке с динамиком в той же комнате. Микрофон услышавшей колонки на это
  время глушится, уточняющий вопрос она слушает сама.

## Микрофон, фразы активации и сон

- **Тихий микрофон.** Панель → Колонка → «Настройки колонки»: усиление ES7210 на плате
  (держите 30–36 дБ), цифровое усиление на ПК (по умолчанию +6 дБ) и канал микрофона.
  Прошивка шлёт оба канала ES7210, ПК сам выбирает тот, где громче.
  «Порог громкости речи» в Настройках сравнивается с уровнем *после* усиления.
- **Своя фраза активации** (Ассистент → «Свои фразы»): любые русские слова, например
  `алекса, колонка`. Они ищутся в распознанном тексте: «Колонка, выключи свет» выполнится
  целиком. Модель openWakeWord (Алекса и др.) работает параллельно, её можно выключить.
  Слово самой модели тоже ищется в тексте: если модель пропустила русское «Алекса», а
  распознавание его услышало, колонка всё равно начнёт слушать (на ≈1 с позже). В журнале
  дополнения тогда видно, сколько набрала модель: `wake model missed 'алекса' (best score 0.52…)`.
- **Режим сна** (Колонка → «Режим сна», переключатель «Режим сна» в HA, или голосом «спи»).
  Во сне дневник пишется, кольцо не светится, ключевое слово игнорируется.
  «Не спи» / «проснись» будят без ключевого слова до конца ночного окна расписания.
  Средняя кнопка на плате работает всегда.

## Телевизор рядом с колонкой

Звук ТВ из микрофона не вычитается (у платы нет эхоподавления по ТВ), поэтому HA Voice
отличает **кто говорит**. Сначала запишите голоса домашних (вкладка «Голоса», 3–5 записей
с колонки на человека), затем Настройки → «Чьи команды выполнять»:

- **Отказывать незнакомым голосам и ТВ** — команды выполняются только знакомым голосам.
- **Не записывать в дневник неизвестные голоса** — дневник только для своих.
- **Телевизор** — его `media_player` в HA. Пока ТВ включён (`on`/`playing`/`paused`):
  речь из ТВ не пишется в дневник, порог узнавания +10 %, а ключевое слово из ТВ не зажигает
  кольцо — колонка молча записывает фразу и реагирует, только если узнала голос.
- **Телевизор во время команды** — сразу после сигнала «слушаю» ТВ делается тише (по
  умолчанию до 25 % текущей громкости), выключается звук или ставится пауза и возвращается,
  как только запрос записан. На время ответа его можно глушить отдельной настройкой. Если
  громкость за это время поменяли вручную, она остаётся вашей. Через 90 с ТВ возвращается
  в любом случае.

**Если голос узнаётся плохо:**

1. Записывайте голос **с той колонки и с того места**, откуда обычно говорите, а не с
   телефона: модель сравнивает тембр вместе с акустикой комнаты и микрофона.
2. Журнал команд (вкладка «Ассистент») показывает у каждой команды «голос NN %» и
   «Чей это голос?». Выберите себя у 2–3 команд с каждой колонки — запись добавится к
   голосу. Каждая запись сравнивается отдельно, поэтому команда издалека совпадёт с
   такой же дальней записью, даже если ближние звучат иначе.
3. Порог («Настройки» → «Порог узнавания голоса») ставьте между процентами своих команд
   и процентами ТВ/гостей из журнала. Обычно 55–65 %.
4. Для узнавания к команде добавляется само ключевое слово (≈1,5 с): короткое «выключи
   свет» одно слишком короткое, чтобы различить голоса.

## Что где настраивается (всё в панели HA Voice)

| Вкладка | Что |
|---|---|
| Колонка | статус платы, уровень микрофона, громкость, «сказать», прошивка USB/OTA (Waveshare и XVF3800) |
| Дневник | живая расшифровка всего, что слышит колонка |
| Голоса | запись голосов с колонки, проверка записи |
| Озвучка | голос Kokoro (Света / Маша / Дима), проверка, состояние загрузки и перезапуск |
| Ассистент | ключевое слово, кто отвечает (агент HA или LLM), своя LLM на сервере, журнал команд |
| Настройки | доступ к HA, фильтр чужих голосов, пороги дневника |

## Необязательно: Assist / Wyoming

Порты `10350` (STT через фильтр голосов) и `10351` (Kokoro TTS) по‑прежнему открыты —
если хотите использовать HA Voice в обычном Assist на других устройствах.

## Старая прошивка room_diary

Платы с пакетом `room_diary_package.yaml` продолжают писать дневник (протокол `HV01`),
но не умеют отвечать голосом. Перепрошейте их на `ha-voice-satellite.yaml`.

## Перенос на другой сервер

1. Остановите compose/add-on.
2. Скопируйте том `data/` (`models`, `speakers`, `dialogues`, `config`, `firmware`).
3. Поднимите на новой машине, поменяйте «Сервер HA Voice» у колонки и адрес в интеграции.
